# State transition coverage

Complete typed SSZ schemas cover BeaconState, BeaconBlock, SignedBeaconBlock and their nested fields across Phase0, Altair, Bellatrix, Capella, Deneb, Electra, Fulu and Gloas. Decoding and encoding enforce canonical offsets, boolean encodings, bitfields and exact mainnet/minimal collection bounds. Roots commit to every field. Gloas uses the specified progressive containers, lists and bitlists, including typed execution payload envelopes and builder/PTC fields.

The `ssz` wrappers retain the selected fork and preset. States expose the decoded slot, genesis identity, fork versions and latest header. Blocks derive headers from the complete body root. Signed blocks expose both the signed container root and the unsigned message root. These are structural interfaces: signatures, state transitions and network identity must be validated separately. Progressive lists have no legacy SSZ capacity; consensus operation limits and input resource limits remain contextual checks.

Implemented deterministic helpers are scalar and complete-mapping swap-or-not shuffling, shuffled committee partitioning, seed construction, integer square root, and checked binary Merkle branch verification. The complete mapping shares each round pivot and source hash; independent scalar equivalence tests cover 256-index source boundaries. Mainnet and minimal shuffle rounds are caller-supplied, as required by fixture configuration.

The Phase0 processing module implements transactional slot replay and the complete ordered epoch kernels: justification/finalization, attestation rewards and inactivity penalties, activation/exit churn, slashing, hysteresis, voting/reset updates and historical roots. Empty slots share cached field roots and update root rings incrementally; an independent complete-schema comparison covers epoch boundaries and ring wrap. All 122 published Phase0 slot/epoch cases pass against complete post-state bytes and roots, independently of the structural SSZ corpus.

Strict signed Phase0 block import additionally checks the proposer signature, header/parent/body commitment, RANDAO reveal, execution-data votes, required deposits, Merkle deposit proofs, deposit proof-of-possession semantics, proposer/attester slashings, committee aggregate attestations, voluntary exits and committed post-state root. A failure leaves the original state unchanged. Runtime signatures cannot be disabled through these production entry points. Standalone component kernels do not establish whole-block validity.

Published Phase0 operation and signed-block coverage passes all 352 cases: 346 use mandatory BLS, and six artificial cases explicitly request the fixture-only BLS-disabled namespace. Production functions always instantiate verification independently; there is no global toggle or public boolean policy. The optional `spec-tests` feature exposes only artificial fixture entrypoints and never returns authoritative runtime validation proofs.

Altair processing implements the exact irregular state upgrade, translated participation, real aggregate sync committee keys, inactivity scores, weighted participation rewards, all ordered epoch components, cached full-state slot roots, mandatory signed-block verification and sync aggregate incentives. All 366 authenticated published Altair processing, upgrade, sync aggregate, signed block and slot cases pass with real BLS verification. Another 271 published common operation cases pass: 265 with mandatory BLS and six explicitly artificial fixture contexts. This gives 637 passing Altair processing cases, separate from the structural SSZ corpus.

Bellatrix processing implements its concrete upgrade, fork-specific penalties, complete shared epoch kernels, cached full-state slot roots and strict consensus operations. A restoring common-state view moves collection buffers through shared kernels without cloning the validator registry; its partial container root never replaces the full fork state commitment. Pure payload checks validate the committed parent, pre-reveal RANDAO, exact slot timestamp. Signed import invokes a mandatory asynchronous execution adapter inside the atomic transition. The first execution payload also requires separate verified terminal-block eligibility; a new-payload VALID reply alone cannot establish it. Runtime adapters must reject missing evidence, optimistic statuses, mismatched hashes and transport failures. Published Bellatrix transition coverage remains pending.

Capella processing adds the complete upgrade, historical summaries, expected withdrawal sweeps and counters, mandatory BLS address changes, cached complete state roots and atomic imports with required typed execution verification. Deneb processing adds its upgrade, blob header fields, configured commitment limits, ordered versioned hashes and parent beacon root for execution, capped activation churn, extended attestation inclusion and fixed Capella voluntary-exit signature domains. Focused real-signature and atomicity regressions pass; published processing coverage for these two forks remains pending. Execution callback mocks test boundaries and rollback only; they do not establish actual execution validity.

Electra implements independent balance queues, credential-dependent effective balances, multi-committee attestations, execution requests and mandatory typed V4 import. Fulu adds the exact proposer lookahead, BPO schedule and changed deposit rules. Gloas imports signed beacon blocks separately from immutable signed execution envelope verification, with progressive state roots, deferred parent requests, builder accounting, payment quorums, payload availability and PTC windows. A checked fork dispatcher processes old epoch rules before ordered scheduled upgrades, including equal activation epochs. Focused signature, rollback and full-root regressions pass; authenticated later-fork processing corpora are being exercised separately. Complete genesis construction, every required fork-choice/light-client/network handler, runtime engine adapters for all versions and full data-availability admission remain incomplete. The complete-transition capability gate returns false for every fork; requiring a transition returns UnsupportedFullTransition. Structural root matching and partial protocol coverage do not enable live chain import.

Transition kernels compute against a candidate state, validate the post-state root and mandatory signatures, then commit. Execution and terminal eligibility callbacks run inside the atomic import when required. Published fixture archives, reference schema research and scratch files belong under work and remain untracked. The specification runner owns published full-container fixture coverage; its results must distinguish SSZ conformance from transition validation.
